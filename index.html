xabi Local Development Orchestrator

xabi is a user-space local web development orchestrator compiled from the Go standard library. It manages native system binaries (nginx, php-fpm or php-cgi.exe, mariadbd, mkcert, and cloudflared) directly under the active user account without root system daemons, Windows service wrappers, or containers.

Configuration, database storage, and runtime sockets follow the XDG Base Directory specification. Select Windows or Linux in the navigation bar to switch commands, file paths, upstream sockets, and completion instructions across this page.

Runtime Model User-space native binaries
Core Stack Nginx · PHP · MariaDB · mkcert
Active Platform Windows (PowerShell)
XDG Category Resolved Path (Windows) Contents
Config ($XDG_CONFIG_HOME) %USERPROFILE%\.config\xabi\ config.toml, sites.toml, nginx/, certs/, php/
Data ($XDG_DATA_HOME) %USERPROFILE%\.local\share\xabi\ db/ (MariaDB datadir), bin/ (PHP shims/symlinks), php/
Runtime ($XDG_RUNTIME_DIR) %TEMP%\xabi\ .pid files, log files, and Nginx temp buffers
Hosts File & Default PHP Upstream C:\Windows\System32\drivers\etc\hosts • 127.0.0.1:9000 Managed entries enclosed by # BEGIN xabi and # END xabi

Binary Installation #

        
Compile ./cmd/xabi from source, place the executable in the user binary directory, and configure PATH.


        

          
Build and install on Windows

          
Clone the repository, compile bin\xabi.exe, and copy the executable into %USERPROFILE%\.local\share\xabi\bin. Placing the binary in this directory keeps it alongside the php.cmd and php-cgi.cmd shims generated by xabi php.

          

            

              PowerShell
              
            

            
git clone https://github.com/yusrb2/xabi.git
cd xabi
go build -trimpath -ldflags="-s -w" -o bin\xabi.exe .\cmd\xabi

$binDir = "$env:USERPROFILE\.local\share\xabi\bin"
New-Item -ItemType Directory -Force $binDir | Out-Null
Copy-Item .\bin\xabi.exe "$binDir\xabi.exe" -Force

          


          
Configure user PATH

          
Append %USERPROFILE%\.local\share\xabi\bin to the user PATH environment variable and verify the binary in a new terminal session:

          

            

              PowerShell
              
            

            
$binDir = "$env:USERPROFILE\.local\share\xabi\bin"
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
if ($userPath -notlike "*$binDir*") {
    [Environment]::SetEnvironmentVariable("Path", "$userPath;$binDir", "User")
}

xabi version

          

        


        

          
Build and install on Linux

          
Execute make install to compile a static binary (CGO_ENABLED=0) and install it to ~/.local/bin/xabi. Pass PREFIX=/usr/local for a system-wide installation.

          

            

              Bash / Zsh
              
            

            
git clone https://github.com/yusrb2/xabi.git
cd xabi
make install
# System-wide alternative: sudo make PREFIX=/usr/local install

          


          
Configure shell PATH

          
Add both ~/.local/bin and ~/.local/share/xabi/bin (active PHP symlinks) to your shell profile (~/.bashrc or ~/.zshrc):

          

            

              Bash / Zsh
              
            

            
export PATH="$HOME/.local/bin:$HOME/.local/share/xabi/bin:$PATH"

xabi version

Diagnostics and Initialization #

        
Link system binaries, provision the XDG directory layout, grant write access on the system hosts file, and verify port availability.


        
xabi locates nginx (required) and optional binaries (php-fpm or php-cgi, mariadbd or mysqld, mkcert, and cloudflared) inside %USERPROFILE%\.local\share\xabi\bin, the PATH environment variable.


        

          
Initialize environment and run diagnostics

          
Verify that the directories containing nginx.exe, php-cgi.exe, mariadbd.exe, and mkcert.exe are available in PATH. Standard PHP installations under C:\php*, C:\tools\php*, C:\laragon\bin\php\php-*, Chocolatey, and Scoop are detected automatically by xabi php.

          

            

              PowerShell
              
            

            
# Preview planned directories, templates, and setup steps without modifying disk state
xabi init --dry-run

# Create XDG layout, config.toml, nginx.conf, MariaDB datadir, and install mkcert root CA
xabi init

# Check binaries, ports 80/443/3306, and hosts file permissions
xabi doctor

          


          
Configure hosts file permissions

          
Grant Modify access on C:\Windows\System32\drivers\etc\hosts once from an elevated PowerShell session so xabi add and xabi rm run without elevation:

          

            

              PowerShell (Administrator)
              
            

            
icacls "$env:SystemRoot\System32\drivers\etc\hosts" /grant "${env:USERNAME}:(M)"

          


          

            Port binding on Windows: Windows does not use POSIX capabilities (setcap). If xabi doctor reports port 80 or 443 in use, stop conflicting services such as IIS or Apache, or edit [ports] in %USERPROFILE%\.config\xabi\config.toml.
          

        


        

          
Configure hosts ACL, capabilities, and initialize

          
Install native packages (nginx, php-fpm, mariadb, mkcert, libcap), grant user write ACL on /etc/hosts using setfacl, and execute xabi init to provision the XDG hierarchy, initialize MariaDB, and apply cap_net_bind_service to nginx:

          

            

              Bash
              
            

            
# Grant write ACL on /etc/hosts to the current user
sudo setfacl -m u:$USER:rw /etc/hosts

# Preview planned actions without modifying system files
xabi init --dry-run

# Provision XDG directories, config.toml, nginx.conf, MariaDB datadir, setcap, and mkcert CA
xabi init

# Apply cap_net_bind_service manually if xabi init ran without privileges
sudo setcap 'cap_net_bind_service=+ep' "$(readlink -f "$(command -v nginx)")"

# Verify environment readiness
xabi doctor

          

        


        
Flags and default configuration

        
Pass --dry-run to inspect planned actions without writing to disk, or --force to overwrite existing config.toml, nginx.conf, and mime.types files. Default config.toml values are tld = "test", web_server = "nginx", php_default = "system", services = ["nginx", "php-fpm", "mariadb"], and ports 80, 443, and 3306.

Service Orchestration #

        
Start, reload, stop, and inspect the live state of nginx, php-fpm (php-cgi.exe on Windows), and mariadb in user-space.


        
Lifecycle commands are idempotent and accept an optional list of service names. In addition to canonical names (nginx, php-fpm, mariadb), aliases php, php-cgi, mysql, and mysqld are supported.


        

          

            PowerShell
            
          

          
# Start all configured services or specific services only
xabi up
xabi up nginx php-fpm

# Inspect RUNNING/STOPPED state, PID, endpoint, and RSS memory (alias: st)
xabi status
xabi st

# Perform a graceful reload (--reload) or full stop-start restart
xabi restart --reload
xabi restart nginx

# Stop services in reverse order (mariadb -> php-fpm -> nginx)
xabi down

        


        

          

            Windows process behavior: Daemons are started in the background using HideWindow and CREATE_NEW_PROCESS_GROUP without console windows. php-cgi.exe binds to 127.0.0.1:9000 (PHP_FCGI_CHILDREN=4, PHP_FCGI_MAX_REQUESTS=1000), PID and process tree RSS metrics are read via kernel32.dll and psapi.dll, and --reload invokes nginx.exe -s reload.
          

        


        

          

            Linux process behavior: Daemons are detached with Setsid: true, PID and process tree RSS memory are read directly from /proc/<pid> with orphan PID recovery, --reload sends SIGHUP to Nginx and SIGUSR2 to PHP-FPM, and xabi down sends SIGTERM (with SIGKILL fallback) before removing .pid and .sock files.

Virtual Hosts and Reverse Proxy #

        
Register local *.test domains, configure reverse proxies with WebSocket upgrade headers, and manage site entries.


        
    
          
  • Project auto-detection: When public/index.php exists, xabi add configures a PHP virtual host targeting the /public subdirectory (Laravel/Symfony). If index.php, --php, or a .php-version file exists, the directory is configured for PHP; otherwise it is served as static HTML (try_files $uri $uri/ =404).
    • 
          
  • WebSocket reverse proxy: Passing --proxy <port|host:port> (for example 3000, :3000, or 127.0.0.1:8080) renders an Nginx location block with proxy_http_version 1.1, Upgrade $http_upgrade, Connection "upgrade", and X-Forwarded-* headers.
    • 
          
  • Atomic registration: Writes the virtual host file at %USERPROFILE%\.config\xabi\nginx\sites\<domain>.conf, updates sites.toml, injects 127.0.0.1 <domain> into the # BEGIN xabi block of the hosts file, and reloads Nginx if running.
    • 
        


        

          

            PowerShell
            
          

          
# Register the current directory (domain defaults to sanitized directory name -> laravel-app.test)
cd C:\Dev\laravel-app
xabi add

# Register a reverse proxy target with WebSocket support
xabi add myapp --proxy 3000
xabi add api --proxy 127.0.0.1:8080

# Specify an explicit directory and PHP version
xabi add legacy --dir C:\Dev\legacy-api --php 8.2

# List registered sites, open in default browser, or remove registration
xabi ls
xabi open myapp
xabi rm myapp

Local HTTPS Certificates #

        
Issue locally trusted TLS certificates via mkcert and enable automatic HTTP-to-HTTPS 301 redirects for registered domains.


        
Executing xabi tls generates <domain>.pem and <domain>-key.pem (covering <domain> and wildcard *.<domain>) inside %USERPROFILE%\.config\xabi\certs\. The Nginx virtual host file is updated with return 301 https://$host$request_uri; on HTTP and listen 443 ssl; on HTTPS, followed by an Nginx reload.


        

          

            PowerShell
            
          

          
# Enable TLS for the site matching the current working directory or a named site
xabi tls
xabi tls myapp

# Disable TLS, delete site certificate files, and revert the virtual host to HTTP
xabi tls myapp --off
# Alias: xabi tls myapp --disable

        


        

          Root CA trust: The local certificate authority is installed by mkcert -install during xabi init. If a browser reports an untrusted certificate, re-run mkcert -install and restart the browser process.

PHP Version Management #

        
Inspect installed PHP runtimes, switch the global PHP version, or pin an isolated PHP version per project using .php-version.


        

          

            PowerShell
            
          

          
# List detected PHP installations (* indicates active global) and project .php-version
xabi php

# Switch global PHP version in config.toml, update shims/symlinks, and refresh services
xabi php 8.4
# Alias: xabi php use 8.4

# Pin a specific PHP version in the current project directory (.php-version)
cd C:\Dev\api
xabi php pin 8.3

        


        
Platform upstream isolation

        

          

            

              
                

                  Mechanism
                  Windows Implementation
                

              
              
                

                  Upstream isolation
                  Global default listens on 127.0.0.1:9000. Pinned versions map deterministically to 127.0.0.1:90xx using 9000 + major*10 + minor (for example, PHP 8.1 → 9081, 8.2 → 9082, 8.3 → 9083, 8.4 → 9084).
                

                

                  Discovery and shims
                  Scans %USERPROFILE%\.local\share\xabi\php\<ver>, C:\php*, C:\tools\php*, C:\laragon\bin\php\php-*, Chocolatey, Scoop, and PATH. Switching the global version writes php.cmd and php-cgi.cmd shims in BinDir.
                

              
            

          

        


        

          

            

              
                

                  Mechanism
                  Linux Implementation
                

              
              
                

                  Upstream isolation
                  Global default listens on unix:$XDG_RUNTIME_DIR/xabi/php.sock. Pinned versions spawn dedicated pools configured in ~/.config/xabi/php/php-<ver>.conf listening on unix:$XDG_RUNTIME_DIR/xabi/php-<ver>.sock (for example, php-8.3.sock).
                

                

                  Discovery and symlinks
                  Scans ~/.local/share/xabi/php/<ver>, PATH, /usr/bin, /usr/local/bin, and /usr/sbin. Switching the global version atomically updates the php and php-fpm symlinks in ~/.local/share/xabi/bin/.
                

              
            

          

        


        
When xabi add is invoked without --php, it walks the project directory and its nearest parent directories to resolve any existing .php-version file.

Operational Utilities #

        
Open raw configuration files, stream service logs, expose local sites over public tunnels, manage MariaDB databases, and generate shell completion scripts.


        
Configuration, logs, tunnels, and database

        

          

            PowerShell
            
          

          
# Open config.toml, nginx.conf, PHP config, sites.toml, or a site vhost in $EDITOR
xabi conf
xabi conf nginx
xabi conf myapp --path        # print the resolved file path only

# Stream service or site logs (-n line count, --no-follow print and exit, --access access log)
xabi log nginx -n 50
xabi log nginx --access --no-follow
xabi log mariadb

# Expose a local site over a public tunnel via cloudflared (default) or ngrok
xabi share myapp
xabi share myapp --provider ngrok

# Manage MariaDB (--host=127.0.0.1 --port=3306 --user=root)
xabi db ls
xabi db create myapp_db
xabi db shell myapp_db
xabi db drop myapp_db --force

        


        
Shell completion

        

          
Load dynamic PowerShell completion (covering commands, services, and registered site names from xabi ls) for the current session or persist it in $PROFILE:

          

            

              PowerShell
              
            

            
# Evaluate in the active PowerShell session
xabi completion powershell | Out-String | Invoke-Expression

# Persist in $PROFILE
Add-Content -Path $PROFILE -Value "`nxabi completion powershell | Out-String | Invoke-Expression"

          

        


        

          
Generate and install shell completion scripts for Bash, Zsh, or Fish (covering commands, services, and dynamic site names from xabi ls):

          

            

              Bash / Zsh / Fish
              
            

            
# Bash
mkdir -p ~/.local/share/bash-completion/completions
xabi completion bash > ~/.local/share/bash-completion/completions/xabi

# Zsh (ensure ~/.zsh/completions is in fpath before compinit)
mkdir -p ~/.zsh/completions
xabi completion zsh > ~/.zsh/completions/_xabi

# Fish
mkdir -p ~/.config/fish/completions
xabi completion fish > ~/.config/fish/completions/xabi.fish

Command Reference #

        
Complete reference for all 19 commands registered in cmd/xabi and internal/commands.


        

          

            
              

                Command
                Syntax and Flags
                Description
              

            
            
              

                init
                xabi init [--dry-run] [--force]
                Create XDG directories, config.toml, nginx.conf, MariaDB datadir, Linux setcap, and run mkcert -install.
              

              

                doctor
                xabi doctor
                Verify XDG layout, required/optional binaries, ports 80/443/3306, hosts file permissions, and cap_net_bind_service.
              

              

                up
                xabi up [service...]
                Start nginx, php-fpm / php-cgi, and mariadb idempotently.
              

              

                down
                xabi down [service...]
                Stop services in reverse order and remove runtime .pid and .sock files.
              

              

                restart
                xabi restart [--reload] [service...]
                Restart services, or perform a graceful reload (SIGHUP/SIGUSR2 on Linux, nginx -s reload on Windows).
              

              

                status (st)
                xabi status [service...]
                Display RUNNING/STOPPED state, PID, endpoint, and RSS memory with orphan PID recovery.
              

              

                add
                xabi add [name] [--proxy <port|host:port>] [--dir <path>] [--php <ver>]
                Auto-detect Laravel/PHP/static roots or reverse proxy WebSocket upstreams, generate Nginx vhost, and update the hosts file.
              

              

                rm
                xabi rm <name>
                Remove site .conf, TLS certificates, sites.toml entry, and hosts file entry.
              

              

                ls
                xabi ls
                Print registered sites (DOMAIN, TARGET, TLS, PHP).
              

              

                open
                xabi open [name]
                Open site URL (http:// or https://) in the default system browser.
              

              

                tls
                xabi tls [name] [--off|--disable]
                Issue local certificates via mkcert with HTTP 301 redirect, or disable TLS for a site.
              

              

                php
                xabi php [version | use <ver> | pin <ver>]
                List detected PHP installations, switch the global version, or write .php-version per project.
              

              

                conf
                xabi conf [config|nginx|php|sites|<site>] [--path]
                Open a configuration file in $VISUAL/$EDITOR or print the resolved path with --path.
              

              

                log
                xabi log [nginx|php|mariadb|<site>] [-n <lines>] [--no-follow] [--access]
                Stream service or site log files cross-platform.
              

              

                share
                xabi share [name] [--provider <cloudflared|ngrok>]
                Expose a local site over a public tunnel via cloudflared or ngrok with host header forwarding.
              

              

                db
                xabi db [shell [name] | ls | create <name> | drop <name> [--force]]
                Manage MariaDB/MySQL databases or open an interactive SQL shell without password prompts.
              

              

                completion
                xabi completion <bash|zsh|fish|powershell>
                Print shell completion script covering commands, services, and registered sites from xabi ls.
              

              

                help
                xabi help [command] (-h, --help)
                Display command overview or usage details for a specific command.
              

              

                version
                xabi version (-V, --version)
                Print the installed xabi binary version.
